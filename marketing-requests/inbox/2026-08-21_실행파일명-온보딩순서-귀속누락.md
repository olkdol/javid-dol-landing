## ① 🔴 `start.bat` 안내가 실제 배포물과 다릅니다 (41곳)

### 무엇이 틀렸나
랜딩은 이렇게 안내합니다:
> *"Double-click **start.bat** — dependencies install automatically and your dashboard opens"*

**사용자가 실제로 받는 건 `.exe`(윈도우) / `.app`(macOS) 실행파일입니다.**
(2026-08-21 사용자 확인. 배포물 자체는 `.zip` 이고 그 안에 실행파일이 들어 있습니다:
`JaviD_Future_Bot_Bitget_Windows.zip` / `..._macOS.zip` — 다운로드 헤더로 확인.)

### 왜 지금 급한가
이 프로젝트에서 가장 비싼 실패 유형입니다. **안내한 대로 했는데 그런 파일이 없으면**
사용자는 "내가 뭘 잘못했나"가 아니라 **"이 프로그램 이상하다"** 로 결론냅니다. 이 카테고리의
지배 감정이 의심이라 회복이 안 됩니다. 게다가 이건 퍼널 **최하단**(이미 받은 사람)이라
가장 비싼 트래픽이 여기서 죽습니다.

### 고칠 곳 (`grep -rl "start\.bat" --include=*.html`)
```
bitget-site/   index · ko · ja · fr · es · manual · bitget-signup-api-guide
bybit-site/    index · fr · es · bybit-signup-api-guide
bg-site-update/index
(binance-site 도 같은 문구가 있으면 함께)
```
⚠️ **비트겟만이 아니라 bybit 사이트에도 퍼져 있습니다.** 한 사이트만 고치면 안 됩니다.

### 문구 제안
```
Download → Unzip → Double-click the program
(an .exe on Windows, an .app on macOS)
```
저희 쪽(영상·이메일 CS 템플릿)은 **이미 이 표현으로 통일**해 두었습니다.

## ② 🟠 시작 안내 순서가 퍼널 최대 병목입니다

### 현재
```
1  Download & launch the app
2  Connect your Bitget API key     ← "Paste your key into Settings"
3  Verify in Shadow Mode
```

### 문제
**API 키가 없어도 쉐도우 모드가 완전히 돌아갑니다.** (2026-08-19 배포본 직접 실행 실측:
키 미설정 상태로 기동 → 심볼 20개 로드, 실패 0 → 가상잔고 2,000 USDT, 759개 심볼 시세 수신)

그런데 번호가 붙은 단계는 **키를 먼저 넣으라고 가르칩니다.** 결과:
- **거래소 계정이 없는 사람은 2단계에서 물리적으로 진행이 막힙니다.** 구경조차 못 합니다.
- 계정이 있는 사람도 *"겨우 구경하려는데 벌써 계좌를 연결하래"* 로 읽습니다.
  되돌릴 수 없는 커밋(계좌 연결)을 **학습 이전에** 요구하는 구조라, 사람은 여기서 학습 자체를 포기합니다.

히어로에 `Try Shadow Mode First` 버튼이 있지만, **번호 붙은 단계가 이깁니다** — 사용자는 번호를 따릅니다.

### 요청
2번과 3번의 순서만 바꿔주세요.
```
1  Download & launch
2  Watch it trade in Shadow Mode      ← API 키 불필요, 계좌 불필요
3  Connect your API key when you're ready   (출금 권한 OFF)
```

이건 새 기능이 아니라 **이미 되는 것을 되는 순서로 적는 일**입니다.
저희 쇼츠 1편(`skip-step-one`)이 통째로 이 문제를 우회하는 데 쓰이고 있습니다 — 순서가 바뀌면
그 우회 비용이 사라집니다.

### 참고 — 알려진 버그 (제품팀 확인 필요, 랜딩 작업은 아님)
`/api/shadow/toggle` 과 `/api/control/start` 가 **500을 반환하면서 실제로는 정상 동작**합니다.
사용자는 500을 보고 "고장"으로 읽고 끕니다. 랜딩에서 고칠 일은 아니지만,
2단계 문구에 *"에러가 보여도 실제로는 켜집니다"* 를 한 줄 넣으면 이탈이 줄 것 같습니다.

## ③ 🟡 언어 페이지 4개에 유입 출처 스크립트가 없습니다

2026-08-10 요청서(`REQUEST_landing-agent_download-attribution.md`)로 넣어주신 귀속 추적이
**영어 루트에서는 완벽하게 작동합니다.** 오늘 실제 브라우저로 end-to-end 검증했습니다:

```
bg.javidtrading.com/?utm_source=youtube&utm_medium=shorts&utm_campaign=diag-test
  → sessionStorage: {"us":"youtube","um":"shorts","uc":"diag-test"}
  → 다운로드 링크: /api/download?platform=windows&us=youtube&um=shorts&uc=diag-test&lp=%2F  ✅
허브 경유(www → bg)도 UTM 이 그대로 전달됩니다  ✅
```

**그런데 언어 페이지 일부에는 스크립트가 아예 없습니다.**

| 페이지 | 캡처 스크립트 | 링크 장식 | 결과 |
|---|---|---|---|
| `/` `/ja` `/fr` `/es` | ✅ | ✅ | 정상 |
| **`/ko` `/pt` `/tr` `/vi`** (bitget-site) | ❌ | ❌ | **무조건 `direct`** |
| `/ko` `/pt` `/tr` `/vi` (binance-site) | ✅ | ❌ | **무조건 `direct`** |
| `/zh` | — | — | **404 (페이지 없음)** |

`/ko` 에서 실제로 다운로드 링크를 클릭해 보니 href 가 **그대로**였습니다
(`/api/download?platform=windows` — 파라미터 0개).

### 왜 중요한가
**한국이 비트겟 다운로드의 최대 국가입니다(80건 중 24건).** 그 트래픽의 출처를 통째로 못 봅니다.
그리고 binance-site 쪽은 **캡처는 되는데 장식이 없어서** 값을 모아만 두고 안 쓰는 상태입니다 —
이쪽이 더 아깝습니다(고칠 게 절반뿐).

### 요청
- `index.html` 의 두 스크립트(`captureSource` 인라인 + `attachDownloadSource`)를
  `ko/pt/tr/vi` 에 그대로 복사 (bitget-site: 둘 다 / binance-site: `attachDownloadSource` 만)
- `/zh` 404 — 중국어(번체) 영상을 게시 중이므로 페이지를 만들거나, 없다면 `hreflang` 에서도 빼주세요

### ⚠️ 함정 (2026-08-10 요청서와 동일하니 그대로 유지해 주세요)
- `document.referrer` 가 우리 도메인이면 **비워야** 합니다(사이트 내 이동은 출처가 아님)
- 이미 `jfb_src` 가 있으면 **덮어쓰지 말 것**(첫 유입이 진짜 출처)
- 다운로드 링크 선택자가 `a[href^="/api/download"]` 라 **절대경로 링크는 안 잡힙니다.**
  언어 페이지에서 링크를 절대경로로 쓰고 있다면 상대경로로 맞춰주세요

## 검증 방법 (작업 후)

①②는 브라우저로 눈으로 확인하면 됩니다.
③은 이렇게 확인하실 수 있습니다 — **다운로드를 완료하지 않고** 확인하는 방법입니다:

```js
// /ko 에 ?utm_source=test 를 붙여 접속한 뒤 콘솔에서
const a = document.querySelector('a[href^="/api/download"]');
a.addEventListener('click', e => e.preventDefault(), true);   // 실제 다운로드 차단
a.click();
a.getAttribute('href');   // ← us/um/uc 가 붙어 있으면 성공
```

⚠️ `/api/download` 를 그냥 호출하면 **다운로드 카운터에 집계됩니다.**
(저희가 오늘 점검하다 4건을 잘못 쌓았습니다. 위처럼 `preventDefault` 로 막고 href 만 읽으세요.)
