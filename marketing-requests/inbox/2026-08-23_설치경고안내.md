# 랜딩 요청 — 설치 경고(OS 차단) 안내 섹션 추가

> 요청자: 해외마케팅 에이전트 팀 · 2026-08-23
> 붙여넣을 HTML: 같은 폴더의 `2026-08-23_설치경고안내_붙여넣기블록.html` (영문/한글 2벌, 인라인 스타일)

## 왜

개인이 배포한 실행파일은 `.exe` 든 `.app` 든 **거의 예외 없이** OS 가 실행을 막습니다.
지금은 그 경고를 만난 사람이 **혼자 판단하다 그만둡니다.** 다운로드까지 온 가장 비싼 트래픽이
여기서 죽는데, 우리는 안내를 한 줄도 안 하고 있습니다.

미리 알려주면 그 경고는 **이탈 트리거에서 예상된 절차로 성격이 바뀝니다.**
반대로 예고 없이 만나면 "역시 이상한 프로그램"이라는 기존 의심을 **OS 가 대신 확인해주는**
꼴이 됩니다. 이 카테고리에서 가장 비싼 실패 유형입니다.

## 어디에

1. **다운로드 버튼 바로 아래** (주 위치)
2. **다운로드 모달(`jfb-dlgate`) 안** — 다운로드하는 100% 가 보는 유일한 지점

## 무엇을 (블록 구조)

**"그냥 눌러서 넘기세요" 로 쓰지 않았습니다.** 그건 나쁜 습관을 가르치는 것이고
"믿지 말고 확인하세요" 라는 우리 전제와도 어긋납니다. 순서를 이렇게 잡았습니다:

1. **왜 뜨는가** — 유료 코드 서명 인증서가 없어서. 사업자 등록 + 연 갱신이 필요하고,
   개인이 만든 프로그램은 거의 다 마찬가지. **바이러스 검사 결과가 아니다.**
2. **믿기 전에 확인하는 법** — VirusTotal(실행 전) · 리소스 모니터/`lsof -i -P`(실행 후, 호스트 2곳)
   → 이 두 방법은 **우리 프로그램만이 아니라 앞으로 받을 어떤 파일에도** 쓰므로,
     블록 자체가 방문자에게 남는 값이 됩니다.
3. **진행하는 법** — OS 별 정확한 절차

## ⚠️ macOS 절차가 최근 바뀌었습니다 (반드시 이대로)

| OS | 절차 |
|---|---|
| 윈도우 | "추가 정보" → "실행" |
| **macOS 15 (Sequoia) 이상** | 한 번 열어 실패시킨 뒤 → **시스템 설정 → 개인정보 보호 및 보안 → "무시하고 열기"** |
| macOS 14 이하 | 우클릭 → 열기 → 열기 |

**Sequoia 부터 Control-클릭(우클릭) → 열기 우회가 제거됐습니다.** 오래된 안내를 그대로 쓰면
맥 사용자(다운로드의 35%)가 안내대로 했는데 안 되는 상황이 생깁니다.
(15.1 에서는 시스템 설정 경로마저 잠시 깨졌다가 15.2 에서 복구됐습니다.)

## 같은 파일에서 함께 고쳐주셨으면 하는 것 — 다운로드 모달

현재 `jfb-dlgate` 모달 문구가 이렇습니다:

> "Before You Download — **you'll need a Bitget account and API key connected before you can
> start trading with it.** Don't have one yet? … [Sign Up for Bitget & Get API →]"

**다운로드를 누른 그 순간에 계좌·API 키를 요구합니다.** 그런데 **쉐도우 모드는 계좌도 키도
필요 없습니다**(실측: 키 미설정 기동 → 심볼 20개 로드·실패 0 → 가상잔고 2,000 USDT).
계좌 없는 사람이 여기서 "나는 아직 안 되는구나" 하고 나갑니다.

요청: **주 버튼을 "다운로드"로 바꾸고**, 계좌 안내는 보조로 내려주세요.
문구는 *"계좌도 API 키도 없이 먼저 켜보세요. 거래소 계정은 본인 돈으로 매매하기로 정한 뒤에
필요합니다."* 가 사실에 맞습니다.
